# V3 — real-terminal regression runs

I built the task-branch binary from commit `3edbcea4551096f5a684adada04c89c11997c74` and ran it in Herdr pane `wJS:p3`. The scratch config set `refresh_interval = 1`; the scratch cache was separate, and `QMETER_NO_UPDATE_CHECK` was unset. The dashboard used real provider data. Each session stayed open for at least its listed interval after the first fetched frame. The ten target intervals total 165 seconds, more than two minutes.

For each `r` run, I waited for the idle `r refresh · q quit` frame before sending
`r`. The next frame showed `refreshing · q quit`. I sent `q` at the listed
varied times, including during refreshes. All ten qmeter processes exited in
less than one second. Herdr reported the pane's shell as the foreground process
after each quit, so the terminal returned to the shell.

## Resize and slow-provider follow-up

I also tested a live resize in the same Herdr pane. With qmeter running and
`refresh_interval = 1`, the pane viewport changed from 26 to 29 rows. The
screen continued to update. I sent `r` and saw the refreshing frame, resized
the pane again during that refresh, then sent `q`. The process exited in
59 ms and Herdr reported the shell as the foreground process.

For a slow provider, I ran the real binary with `--filter claude` and a local
HTTP proxy. The proxy accepted `CONNECT api.anthropic.com:443`, waited four
seconds, and returned HTTP 502 without opening a TLS connection. While the
provider fetch was waiting on that response, I sent `q`. The process exited
in 64 ms; the shell was restored. The proxy then logged its delayed 502.
