# V2 — renderer regression test

## Red run on the base behavior

Before the renderer fix, I added the renderer seams and the new tests, then ran:

```text
go test ./internal/dash ./internal/dash/layout -run 'Test(ScreenReusesProvidedRenderer|RunPreparesOneDestinationRendererBeforeReadingInput)$'
```

The runtime behavior was still the base behavior from `1b945db`. The tests
failed for the intended reasons:

```text
renderer factory calls = 0, want 1
background query calls = 0, want 1
renderer did not keep the detected light/dark choice
Bubble Tea read input before background detection
Screen created 3 renderers despite a provided renderer
```

The `Screen` test showed that three frames created three renderers. The `Run`
test showed that the input reader started before background detection and
that `Run` did not prepare the destination renderer.

## Green run

The fix prepares a destination-bound renderer in `Run` before creating the
Bubble Tea program. It detects and stores the terminal background once, then
passes the same renderer through the model to each screen frame. `New` also
prepares a renderer before any direct model caller can render. One-shot
commands still call `display.Renderer(w)` as before.

```text
go test ./internal/dash ./internal/dash/layout -run 'Test(ScreenReusesProvidedRenderer|RunPreparesOneDestinationRendererBeforeReadingInput|NewDashboardRendererKeepsDetectedBackground)$'
ok   github.com/Harrison-Blair/qmeter/internal/dash
ok   github.com/Harrison-Blair/qmeter/internal/dash/layout

go test ./internal/dash/...
ok   github.com/Harrison-Blair/qmeter/internal/dash
ok   github.com/Harrison-Blair/qmeter/internal/dash/config
ok   github.com/Harrison-Blair/qmeter/internal/dash/layout
ok   github.com/Harrison-Blair/qmeter/internal/dash/theme
```

The tests check that the renderer factory and background query each run once
before the input reader starts, that frames reuse the supplied renderer, and
that both light and dark query results remain in effect. The existing
`TestRun_QuittingCancelsTheFetchInFlight` test also passed in the dashboard
package suite.
