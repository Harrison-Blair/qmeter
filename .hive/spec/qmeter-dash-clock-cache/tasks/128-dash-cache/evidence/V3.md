# V3 Cache rules test, red then green

Tests in `internal/dash/cache_test.go`:

- `TestCacheSuccessReplacesTheEntry`: a later success replaces windows, balances and fetch time.
- `TestCacheOrdinaryFailureKeepsThePreviousEntryAndItsFetchTime`: two zero-kind failures keep the entry with the fetch time of the success.
- `TestCacheTokenExpiryDropsTheEntry`.
- `TestCacheFirstFailureHasNoEntry`: a first failure yields no entry, so no cached line (the layout side is `TestScreenFailureWithoutCacheShowsOnlyTheErrorLine`, see V4).
- `TestCacheUpdateLeavesTheEarlierCacheUnchanged`: `update` returns a new map.

End to end in the model: `TestViewShowsTheCachedResponseUntilATokenExpiry` (`internal/dash/model_test.go`): success at 14:22:07, a failure shows `◌ cached · fetched 14:22:07 · offline` and the kept `28.0%`, then a token expiry shows `error: offline` and no cached data.

## Repair: an empty success removes the entry

`t128-verifier-1` found in `VERIFIED.md` that an empty success kept the old entry. A later failure then showed obsolete windows and the old fetch time. The amended brief adds the provider set. `cache.update` now takes the IDs of the providers that the model passed to `usage.Run`. Each listed provider without an error has its entry removed before the fresh windows and balances are written. `Model.providerIDs()` supplies the IDs from `Options.Providers`. The existing cache tests pass the set `asked = []string{"codex"}`. Their assertions are unchanged.

New tests:

- `TestCacheEmptySuccessRemovesTheEntry` (`cache_test.go`): success, then `usage.Result{}` with `codex` in the set, removes the entry, and a later failure has no entry.
- `TestViewDropsTheCacheAfterAnEmptySuccess` (`model_test.go`): the verifier's sequence through the real model, with the empty result from `usage.Run` on `providertest.Succeeding("codex", nil)`. After success at 14:22:07, an empty success, and then a failure, the frame shows `error: offline`. The frame does not contain `◌ cached`, `28.0%` or `fetched 14:22:07`.
